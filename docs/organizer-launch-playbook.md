- 첫 실험: 기존 단체방 운영자 1명과 실제 경기 1건을 끝까지 운영

## 1. 한 문장 전략

`앱 설치 없이 모바일·PC 웹에서 Google 로그인 후, 링크 하나로 참가 승인부터 출석·진행·결과까지 운영한다.`

- 참가 신청 단계에서는 전화번호·주소록 입력을 요구하지 않는다. Google 계정 처리 데이터는 공개된 개인정보 안내와 서비스 운영 범위를 따른다.
- 비회원 운영, 가짜 경기, 가짜 기록, 가짜 팀·엠블럼으로 초기 화면을 채우지 않는다.
- 인스타그램 팔로어 수보다 실제 경기 한 건의 완주와 재개설을 먼저 만든다.

## 2. 누구부터 잡을 것인가

첫 고객은 선수가 아니라 아래 조건을 가진 운영자다.

- 이미 농구 단체 채팅방을 운영한다.
- 2주 안에 실제 경기 일정이 있다.
- 참가 확인, 출석, 점수, 결과 정리를 지금 수작업으로 한다.
- 첫 실제 경기의 진행 과정과 가장 큰 불편 한 가지를 BOXTIER에 알려 줄 수 있다.

후보는 공개 농구 모임 계정, 기존 인스타그램 대화 상대, 지인 운영자, 체육관 담당자에서 찾는다. 자동 수집·대량 DM은 하지 않는다. BOXTIER가 후보와 개인화 문구를 준비하고 계정 소유자가 확인 후 직접 보낸다.

## 4. 파일럿 원격 지원

### 운영자에게 제안할 상품

`선정된 파일럿 운영자의 첫 3경기 세팅 지원`

첫 3경기 지원은 장기 제안 범위다. 첫 2주 완료 기준은 운영자 1~2명과 실제 경기 총 1~2건이다.

BOXTIER가 준비한다.

- 경기 생성에 필요한 입력 체크리스트
- 경기 전 10분 원격 확인
- 단체방용 초대문과 경기 링크
- 실제 경기방에서 발급된 출석 QR 사용 안내
- 비동기 체크리스트와 당일 진행 순서
- 경기 후 결과 확정 안내
- 경기 후 15분 원격 회고와 가장 큰 이탈 한 곳 기록

운영자는 이것만 한다.

1. 자기 Google 계정으로 로그인한다.
2. 날짜·장소·정원·경기 방식을 확인한다.
3. 준비된 링크를 자기 단체방에 직접 올린다.
4. 참가자를 승인하고 현장 사실과 결과를 최종 확인한다.

계정 비밀번호 공유와 운영자 사칭은 금지한다. BOXTIER는 자료와 원격 안내를 제공하고, 공유·승인·경기 운영·결과 확인은 실제 운영자가 수행한다.

### 파일럿 순서

1. 후보 3명을 정하고 계정 소유자가 개인화한 문구를 최대 3건 직접 보낸다.
2. 첫 실험은 답한 운영자 1명과 실제 경기 1건으로 시작한다.
3. 경기 전 10분 원격 확인에서 Google 로그인, 경기 정보, 운영자 역할만 확인한다.
4. 운영자는 비동기 체크리스트로 링크 공유·참가 승인·출석·진행·결과 확인을 수행한다.
5. 경기 후 15분 원격 회고에서 완주 여부, 재개설 의사, 가장 큰 이탈 한 곳만 기록한다.
6. 남은 기간에는 같은 운영자의 두 번째 경기와 두 번째 운영자의 첫 경기 중 하나만 선택한다.

단체방·DM 문구:

> 다음 실제 경기 1건을 BOXTIER로 설정해 보실래요? 경기 전 10분 원격 확인과 체크리스트를 드립니다. 앱 설치 없이 모바일·PC 웹에서 Google 로그인한 뒤, 운영자님이 링크 공유·참가 승인·결과 확인을 직접 진행합니다.

## 5. 운영자센터의 역할

운영자센터는 새 관리자 시스템이 아니다. 로그인한 사용자가 기존 권한으로 처리할 경기의 다음 행동만 모은 업무함이다.

- `지금`: 체크인, 진행 중, 경기 후 확인, 이의 처리
- `다음`: 예정된 주최 경기와 배정된 심판 경기
- `지난`: 기록, 취소, 무효 경기 확인
- 실행: 기존 경기방과 같은 권한·단계·모달을 사용
- 다시 만들기: 원본 모집글이 있는 종료 경기의 실제 주최자에게만 제공

전역 관리자 권한, 별도 경기 상태, 중복 점수·출석 로직을 만들지 않는다. 운영자가 해야 할 일을 줄이는 것이 목적이지 모든 기능을 한 화면에 복제하는 것이 아니다.

## 6. 측정할 퍼널

허위 목표 수치를 먼저 만들지 않는다. 아래 실제 사건의 수와 전환만 기록한다.

1. 운영자 제안 확인
2. 첫 경기 운영 신청
3. Google 로그인 완료
4. 경기 생성 완료
5. 초대 링크 열기
6. 참가·대기 신청
7. 운영자 승인
8. 출석 완료
9. 경기 시작
10. 결과 확정
11. 같은 운영자의 다음 경기 생성

핵심 지표는 세 개다.

- 활성화: 운영자의 첫 실제 경기 결과 확정
- 유지: 같은 운영자의 다음 실제 경기 생성
- 병목: 바로 전 단계 대비 이탈이 가장 큰 한 단계

현재 없는 분석값은 `0`처럼 표시하지 않고 `측정 전`으로 둔다. 파일럿 측정 항목에는 개인 연락처, 비공개 대화 원문, 동의가 확인되지 않은 외부 행동을 포함하지 않는다.

## 7. 인스타그램 수정

인스타그램의 역할을 회원 모집 채널에서 실제 경기 운영 증거와 진입 링크 보관소로 바꾼다.

### 프로필

- 소개: `앱 설치 없이 농구 경기 운영. 모바일·PC 웹, Google 로그인.`
- 링크 CTA: `첫 경기 운영 신청`
- 하이라이트: `시작하기 / 경기 운영 / 실제 결과`

### 게시 단위

완료된 실제 경기 1건당 3장 캐러셀 1건만 만든다. 경기 전 예고 게시물은 만들지 않고, 스토리는 이 캐러셀 재공유만 선택적으로 사용한다.

1. 실제 UI: `{YYYY.MM.DD} {지역} 실제 경기 운영 완료`
2. 실제로 사용한 흐름: `링크 참가 → 주최자 승인 → QR 출석`
3. 사실 확인된 결과 화면과 CTA: `첫 경기 만들기`

사용하지 않은 단계는 2번 카드에서 뺀다. 실제 UI가 아닌 설명용 합성 화면, 임의 숫자, 가상 영수증, 가짜 후기·기록·팀·엠블럼은 쓰지 않는다.

### 복사해서 쓰는 캡션

> {날짜} {지역}에서 실제 경기 1건을 BOXTIER로 운영했습니다.
> 참가 링크 공유 → 주최자 승인 → 현장 QR 출석 → 결과 확인까지 웹에서 진행했습니다.
> 앱 설치 없이 모바일·PC 웹, Google 로그인.
> 첫 경기 만들기: https://boxtier.kr/app/create

실제로 거치지 않은 단계는 캡션에서도 뺀다.

### 수동 게시 체크리스트

- [ ] 실제 경기가 끝났고 결과가 확인됐다.
- [ ] 세 카드 모두 해당 경기의 실제 UI 또는 사용 허가가 확인된 사진이다.
- [ ] 이름·프로필·연락처·얼굴·QR·비공개 경기 링크 등 공개할 필요가 없는 식별 정보를 가렸다.
- [ ] 화면·사진·후기 사용 주체와 게시 범위에 대한 동의를 기록했다.
- [ ] 임의 숫자, 합성 경기, 가짜 후기·영수증·기록·팀·엠블럼이 없다.
- [ ] CTA 링크를 모바일과 PC에서 직접 열어 봤다.
- [ ] 계정 소유자가 사실을 최종 확인하고 직접 게시한다.

자동 좋아요·팔로우·댓글·대량 DM은 사용하지 않는다.

## 8. 창업자가 실제로 할 일

- 시작 1회: 후보 3명과 수동 DM 문구 확인
- 첫 실험 1회: 운영자 1명과 경기 전 10분 원격 확인
- 경기별: 비동기 체크리스트 질문 답변과 사실 확인
- 경기 후 1회: 15분 원격 회고와 퍼널 병목 하나 선택
- 2주 종료: 운영자 1~2명, 실제 경기 총 1~2건 상한 확인

후보 조사, 개인화 초안, 초대문, 체크리스트, 게시물 원고, 주간 요약은 도구가 준비한다. 출석 QR은 실제 경기방에서 발급한다. 외부 계정 메시지 발송, 경기 운영, 사실·권한 확인은 사람이 한다.

## 9. 활성화 뒤 수익 순서

수익은 이용자에게 숨기는 방식이 아니라 거래 상대와 조건을 명확히 알리는 방식으로 만든다.

1. 시설·리그 운영 SaaS: 일정, 승인, 출석, 심판, 결과 관리 월 사용료
2. 예약·결제 중개: 실제 대관비, 참가비, 심판 배정 거래의 사전 고지 수수료
3. 정상 제휴 추천: 체육관, 장비, 보험, 촬영 서비스의 표시된 추천 링크
4. 스폰서 패키지: 실제 리그·대회 페이지와 결과물의 명시적 후원
5. 집계 운영 리포트: 충분한 표본, 재식별 위험, 고지·동의 범위를 검토한 뒤 시간대·지역 수요 같은 집계 정보의 제공 가능성 판단

장기 정책 참고: [PLAB 운영 정책](https://policy.plabfootball.com/27e04714-b54b-4c3c-aa10-79759f7f8434)과 [제3자 제공 정책](https://policy.plabfootball.com/privacy/3rd)은 거래·개인정보·제3자 제공을 검토할 때 필요한 고지 항목을 찾는 용도로만 본다. PLAB의 성장·수익성·제휴 성과나 BOXTIER의 시장성을 뒷받침하는 근거로 쓰지 않는다. 실제 수익 기능을 도입하기 전에는 적용 법령과 필요한 동의·고지 범위를 별도로 검토한다.

## 10. 금지선

- 네이버쇼핑 등 외부 서비스 스크래핑으로 방문·검색·순위를 조작하지 않는다.

- 광고·협찬·제휴 링크는 사용자가 알아볼 수 있게 표시한다.
- 처리 목적과 고지·동의 범위를 확인하지 않은 개인정보 제공을 하지 않는다. 서비스 전반의 비수집을 단정하지 않고 단계별 입력값과 처리 목적을 설명한다.
- 실사용 전에는 `인기`, `검증`, `몇 명 사용`, `전환율` 같은 표현을 쓰지 않는다.
