# 2026-06-27 모집/경기 원격 로딩 상태

## 2026-07-21 공통 이미지 상호작용

1. 앱의 실제 `<img>`는 우클릭 이미지 메뉴, 모바일 길게 누르기 이미지 메뉴, 기본 이미지 드래그를 차단한다. 일반 영역의 우클릭 메뉴와 입력 기능은 유지한다.
2. 브라우저 기본 메뉴에서 이미지 관련 항목만 제거할 수 없으므로 이미지 위에서는 메뉴 전체를 열지 않는다. 예외가 꼭 필요한 이미지는 해당 `<img>`에 `data-allow-image-context-menu="true"`를 명시한다.
3. 이 규칙은 실수로 이미지 주소를 복사하는 동작을 줄이는 UX 기준이며, 공개 자산 URL이나 개발자 도구 접근을 막는 보안 경계로 취급하지 않는다.

## 2026-07-20 공통 박스 내부 배치

1. 방 모달, 경기·매칭·플레이 반복 목록 카드, 페이지 hero는 기존 전용 구조를 유지한다.
2. 공통 박스의 padding이나 버튼 높이를 일괄 축소하지 않는다. 같은 행의 내용량이 다르면 카드 높이를 강제로 늘리지 않고 `align-items: start`를 사용한다.
3. 짧은 하위 정보 박스가 네 개면 데스크톱 한 행, `520px` 이하 두 열을 기본으로 한다.
4. 설정 바로가기 세 개는 한 행에 균등 배치한다. `359px` 이하에서는 첫 행 두 개와 마지막 전체 폭 하나로 전환한다.
5. 일정 관계 버튼 네 개는 `2 x 2`, 유형 버튼 다섯 개는 넓은 화면에서 `3 + 2` 균등 행으로 배치한다. `359px` 이하에서는 두 열로 전환하고 마지막 홀수 버튼은 한 행 전체를 사용한다.
6. 제목 옆 아이콘과 작업 버튼은 공간이 허용되면 같은 도구 묶음에 둔다. 좁은 화면에서는 내용이 잘리지 않도록 도구 묶음만 다음 행으로 내린다.
7. 팀 랭킹 기준처럼 같은 성격의 짧은 하위 박스는 세로 나열 대신 균등 열을 우선한다.
8. 경기 상태 다섯 개는 `1120px` 이하에서 `3 + 2`, 랭킹 탭 일곱 개는 좁은 화면에서 `4 + 3` 또는 `3 + 2 + 2`로 마지막 행의 고립 단추를 만들지 않는다.
9. 시즌 운영 체크 네 개는 `360px` 이상에서 `2 x 2`로 배치한다.
10. Discord 알림 네 개는 `2 x 2`, 공개범위 세 개는 데스크톱 한 행과 모바일 `2 + 전체 폭 1`로 배치한다.
11. 방 종류 세 개는 `900px` 이상 한 행, 중간 너비에서는 `2 + 전체 폭 1`로 배치한다. 일반 경기 룰 세 개는 `600px` 이상 한 행이며, 대회 룰 네 개는 `2 x 2`를 유지한다.
12. 프로필 폼의 단독 저장 단추는 전체 열을 사용한다. 업적 카드의 진행 지표는 두 열로 묶고 홀수 마지막 지표는 전체 열을 사용한다.
13. 프로필 아이콘 팝업의 분류 13개는 데스크톱에서 여러 행으로 자연스럽게 줄바꿈하고, `719px` 이하에서는 한 행 가로 스크롤로 보여 아이콘 목록을 아래로 과도하게 밀지 않는다.

## 2026-07-20 프로필 아이콘·팀 엠블럼 편집

1. 개인용 명칭은 `프로필 아이콘`, 팀용 명칭은 `팀 엠블럼`으로 구분한다.
2. 프로필 본문 카드는 현재 아이콘과 `아이콘 변경`, `업적 보기`만 표시한다. `아이콘 변경`은 별도 dialog를 열고 그 안에서 `기본값`, `Discord`, `아이콘`을 고른다. Discord는 연결된 프로필 사진이 있을 때만 선택할 수 있고 `아이콘`은 검수된 300개 카탈로그를 분류 탭과 compact grid로 보여준다. 직접 사진 업로드는 제공하지 않는다.
2-1. 프로필 dialog는 `기본값`과 `아이콘`에서 배경색 사용 여부와 색, 테두리 사용 여부와 색을 함께 편집한다. 배경색이나 테두리를 끄면 각각의 색 control을 비활성화한다. 배경색을 끈 검수 아이콘은 PNG의 투명 영역을 그대로 표시한다. `저장` 성공 시 dialog를 닫고 실패 시 열린 상태에서 원인을 표시한다.
2-1-1. 아이콘 카탈로그의 썸네일 이미지를 누르면 선택 상태를 바꾸지 않고 확대보기 dialog를 연다. 잠긴 아이콘도 확대 확인할 수 있으며 `닫기`, backdrop, `Escape`로 확대보기만 닫는다.
2-2. 프로필 아이콘 분류 탭은 데스크톱 `--ui-button-height-sm`, `720px` 이하에서는 `--ui-button-height`를 사용한다. 기본 색·테두리·저장 control은 모두 `--ui-button-height`로 맞춘다. 선택 상태는 공용 주황 계열을 사용하고 성공 의미가 아닌 초록색을 쓰지 않는다.
2-3. 아이콘 선택 카드는 `70px` 높이와 공용 버튼 글자 크기를 유지한다. 아이콘 설명 문장은 표시하지 않고 이름, 선택 상태, 잠금 표시만 쓴다. `359px` 이하에서는 목록 1열, `360px` 이상 모바일에서는 2열을 사용해 이름 잘림과 과도한 카드 높이를 막는다.
2-4. `/app/profile/achievements`는 분류별 반응형 grid에서 아이콘명, 해금 상태, 정확한 조건, 현재값, 진행률만 보여준다. 외곽은 공용 card, 반복 항목은 공용 control surface를 사용한다. 해금은 주황, 진행률은 파랑, 잠금은 중립색으로 제한하고 네온 그린을 쓰지 않는다.
2-5. 프로필 아이콘 원화는 `80-crown-goat`의 입체 스포츠 편집화 그림체를 기준으로 한다. 굵고 닫힌 검은 외곽선, 제한된 내부 해칭, 실물 농구 장비 비율, 실제 농구공 심·림·네트 구조를 지키며 CGI·저가 3D·판타지 효과를 쓰지 않는다.
2-6. 아이콘 원화는 완전 투명 배경의 정사각 PNG다. 원형 표시 경계에서 사방 5% 안전 여백을 남기고 어떤 윤곽도 잘리지 않아야 한다. 42px에서 주제가 즉시 식별되도록 핵심 실루엣과 대비를 우선한다.
2-7. 단계형 계열은 브론즈·실버·골드·플래티넘·레전드 순으로 소재, 구조, 유니폼·액세서리 등급과 완성도를 올린다. 계열 안에서는 같은 인물, 핵심 사물과 기본 구도를 유지한다. 상위 단계는 상황에 맞는 고급 장비를 최대 1~2개만 추가할 수 있으며 단순 개수 증가나 색상 치환만으로 표현하지 않는다.
2-8. 농구공은 실물 크기와 연속된 8패널 심 구조를 지킨다. 심의 굵기·곡률·교차가 시점에 맞아야 하고 공기 주입구, 밸브 구멍, 원형 포트나 점을 어떤 아이콘에도 표시하지 않는다. 공을 잡는 손은 손가락 수, 관절, 그립 방향과 상완·전완 길이를 함께 검수한다.
2-9. 성인 인물은 현대 스포츠 편집화 기준의 자연스러운 운동선수 비율을 사용한다. 머리는 전체 키의 약 12~13%, 전신은 약 7.8~8.2등신을 기준으로 하며 다리·팔·손·발 길이를 실제 관절 위치에 맞춘다. 동양인 인물은 현대 한국 스포츠 극화체의 작은 머리, 긴 목·팔다리, 얇은 해칭과 자연스러운 현재 한국인 얼굴을 기준으로 하고 시대·국가 고정관념을 과장하지 않는다.
2-10. 서로 다른 업적 계열에는 한국인·백인·흑인 등 인종과 성별을 자연스럽게 분산한다. 같은 5단계 계열 안에서는 동일 인물의 얼굴, 체형, 피부색과 머리 모양을 유지한다.
2-11. 경기 중 아이콘은 암슬리브·무릎 보호대·헤드밴드·농구화처럼 경기력 장비만 사용한다. 경기 전후·운영·서비스 아이콘은 장면에 맞을 때만 시계·목걸이·헤드폰·헤드셋·태블릿을 사용할 수 있다. 같은 인물에게 귀와 목 헤드셋처럼 동일 종류 액세서리를 중복 착용시키지 않는다.
2-12. 신발과 의류에는 상표, 문자, 스우시·체크형 표식이나 특정 브랜드로 읽히는 패널을 넣지 않는다. 일반적인 무지 스포츠 장비 구조로 정리한다.
2-13. 포지션과 전신 인물 아이콘은 승인된 인물 정체성과 동작을 유지하고 머리·발·공·소품이 위아래 또는 원형 경계에서 잘리지 않게 완전한 실루엣으로 채운다.
2-14. 단체 장면의 모든 손은 소유자의 손목·전완·팔꿈치·상완까지 연속해서 보여야 한다. 어깨 위에 출처 없는 손, 다른 아이콘 잔상, 잘린 손가락이나 분리된 신체를 남기지 않는다.
2-15. 다색 농구공은 색 경계를 실제 심과 일치시킨다. 하나의 패널 안에서는 재질의 기본색을 단일 색으로 유지하고 구면 조명 외의 색 그라데이션, 다른 색 침범, 장식용 패널 분할을 쓰지 않는다.
3. 이미지 선택 뒤 공용 크롭 dialog에서 원형 결과 미리보기, 확대·축소, 가로 위치, 세로 위치를 제공한다. 미리보기와 저장 canvas는 같은 계산을 사용한다. 가로 값이 커지면 사진은 오른쪽, 세로 값이 커지면 아래로 이동하며 range 채움은 thumb 중심과 일치해야 한다.
4. 사용자 메시지는 저장 성공과 다음 교체 가능일만 보여준다. 원본·저장 파일의 KB 수치나 압축률은 표시하지 않는다.
5. 팀 사진 저장 버튼은 `저장`으로 표시한다. 정책 안내는 `(처음 한번) 사진을 업로드한 뒤 한 번까지는 바로 변경할 수 있으며, 그 이후에는 마지막 업로드일로부터 30일 뒤에 변경할 수 있습니다.`로 고정한다. 실제 다음 변경 가능일은 엠블럼 옆에만 표시하고 하단 action 안내에서 반복하지 않는다. 실패 메시지는 열린 크롭 dialog 안에서도 보여준다.
5-1. 팀 사진은 현재 사진과 직전 사진만 보관한다. 직전 사진이 있으면 `이전 사진` 보조 버튼을 표시하고, 복원 성공 즉시 현재 사진과 직전 사진을 교체한다.
6. 팀 원본 선택은 `기본값`, `사진 사용` 두 항목으로 통일한다. 기본값으로 전환해도 저장 사진은 삭제하지 않는다.
6-1. 팀 `기본값` 편집은 기존 첫 글자 기본값/팀 이름/약칭 기준, 공백 제외 1~4자 약칭, 스포츠/고딕/명조/모노 글꼴 프리셋, 배경색, 테두리를 한 영역에서 제공한다. 약칭 입력은 2줄 textarea와 `공백 제외 최대 4자 · Enter로 줄바꿈` 안내를 사용하며 별도 줄바꿈 옵션이나 보이지 않는 연속 공백 명령을 두지 않는다. 공백·줄바꿈만 입력한 값은 저장하지 않는다. 공용 `TeamEmblem`이 명시한 약칭 줄바꿈을 그대로 표시하고 팀 이름은 최대 세 줄로 줄여 글자 크기를 자동 조절하므로 별도 이미지 파일을 만들지 않는다.
6-2. 공용 `TeamEmblem`의 첫 글자 `기본값` 크기는 기존 고정 크기를 유지한다. `팀 이름`만 각 줄의 가장 긴 글자 수를 기준으로 기존보다 크게 자동 조절하고 원 안에서 잘리지 않게 단계적으로 축소한다.
6-3. 팀 엠블럼과 프로필 아이콘에서 테두리를 사용하면 후광도 저장된 테두리색을 사용한다. 테두리를 끄면 외곽 후광을 표시하지 않는다. 팀 테두리 사용 여부와 색은 `기본값`/`사진 사용`에 공통인 설정이므로 어느 원본을 선택해도 같은 위치에서 편집·저장할 수 있어야 한다.
7. 데스크톱은 원본 선택과 색상 control을 가로로 배치한다. 프로필 아이콘 dialog의 세 원본 버튼은 모바일에서도 3열 compact 높이를 유지한다. 팀 엠블럼 색상·테두리·저장 control은 viewport가 아니라 실제 관리 카드 너비를 기준으로 배치하고, 카드 내부가 `520px` 이하이면 2열 compact 배치로 전환한다. color input과 저장 버튼은 grid 열보다 큰 최소 너비를 갖지 않아야 한다. 팀 사진 action은 모바일에서 안내를 한 행으로 두고 복원·선택 버튼을 2열로 맞춘다. 아이콘 dialog와 크롭 dialog는 모바일에서 viewport 하단 sheet처럼 배치하고 내부만 스크롤한다.
8. 공용 `ProfileEmblem`은 이름 첫 글자, `TeamEmblem`은 저장된 팀명/약칭 디자인을 기본값으로 사용한다. 프로필 본문, 사이드바 하단 계정 카드, 선수 카드처럼 같은 사용자를 표시하는 모든 위치는 별도 첫 글자나 Discord 전용 렌더링을 만들지 않고 `ProfileEmblem`을 사용한다. 선택한 Discord/팀 이미지 로드 실패 시 기본값으로 되돌아가며, 선택된 배경색과 테두리색은 dark/light 양쪽에서 같은 사용자 값으로 유지한다. Discord 사진은 원형 영역을 채우고 검수 아이콘은 제작 안전영역을 보존하도록 `object-fit: contain`을 사용한다.
9. 팀 사진 신고는 팀 상세 hero의 엠블럼 아래에 작은 보조 액션으로 둔다. 팀 주장과 기본값 엠블럼에는 노출하지 않고, 사유 선택과 접수 버튼만 펼쳐 페이지 흐름을 밀지 않는다.

2. `기록하기`는 이미 끝난 경기의 경기기록방을 만들고, 일정 메뉴가 아니라 플레이 메뉴 기록 확인 흐름에 붙인다.
3. `내 기록`은 모집/초대/참가 UI 없이 프로필 기록용으로 저장하고, 열람은 방모달 형태를 재사용할 수 있다.
3-1. 기본 `/app/create`는 방만들기만 보여준다. 기록방/내 기록 생성은 기록하기 진입(`/app/create?intent=record`)에서만 보여준다.
3-2. 경기기록방 생성 성공 후 `/app/recorder?match=...`로 이동해 방금 만든 기록방을 먼저 선택한다.
3-3. 경기기록방 생성 화면은 1v1에서 상대 선수 1명을 검색해 고르고, 2v2 이상 팀전에서는 팀 선택과 상대 대표 선택만 받는다. 팀전 출전/후보 명단 선택 UI는 기록방 안에서 처리한다.
3-3-1. 사후 경기기록방은 구장 예약, 연령/MMR 참가 제한, 정규전/공식경기 반영, 사전등록, 약속/벌칙 입력을 노출하지 않는다. 구장, 경기일, 실제 경기 룰, 이의제기 시간, 경기 메모만 표시한다.
3-3-2. 공개/비공개 팀전 생성 화면도 팀원 출전/후보 picker를 노출하지 않는다. 생성 화면은 팀과 대표만 고르고, 방 모달에서 각 사이드장이 명단을 확정한다.
3-3-3. 상대 팀/선수 선택 결과는 검색 입력과 같은 한 행에 놓고 공용 `--ui-button-height`를 사용한다. 모바일에서 아래 행으로 내려가도 같은 높이를 유지한다.
3-4. 경기기록방 명단 패널은 각 사이드장에게만 보이며, `출전`, `후보`, `해제` 버튼으로 자기 팀 선수만 고른다.
4. 사전 경기방 UI는 `초대`, `참가`, `참가 확정` 문구를 쓴다.
5. 경기기록방 UI는 `확인 요청`, `기록 확인`, `기록 대상` 문구를 쓴다.
6. 팀전 하단 액션 영역은 기존 초대/수락대기 위치를 재사용하되, 목적에 따라 `팀 선택`, `팀원 소집`, `출전자 확인`으로 라벨을 바꾼다.
7. 팀전은 팀 선택 후 그 아래 팀원 명단을 보여주고, 선수 row에서 `출전/후보/제외`를 고르게 한다.
8. 선택한 선수는 위 슬롯에 미리 보이되, `선수 확정`을 눌러야 저장된 로스터로 표시한다.
9. 팀원에게는 초대 수락 CTA를 주지 않고 홈/Discord `팀원 소집` 알림과 `방 보기` 진입만 제공한다.
10. 공개 팀전은 `팀으로만 참여` 체크박스를 노출하지 않고 팀 파티 전용 안내 박스로 표시한다.
11. 팀전 방모달의 빈 슬롯/후보 슬롯 액션은 사이드장에게만 보이는 `팀원 소집` 흐름이다. 일반 팀원에게는 초대 패널을 열지 않는다.
12. 팀원 소집 UI는 선수별 초대 수락 상태를 보여주지 않고, 출전/후보 명단 저장 결과만 슬롯에 반영한다.
13. 팀전 출전/후보 선택 UI는 로컬 선택 상태를 먼저 보여주고, `선수 확정` 버튼을 눌렀을 때만 저장한다.
14. 경기 메뉴 일정 카드의 A/B 인원 숫자는 현재 출전 슬롯 기준으로 표시하고, 후보 자동충원 예상치는 카드 숫자로 쓰지 않는다.
15. live 경기의 선수 교체 UI는 공통 방 모달 안에서만 보여준다. 후보가 있을 때만 `선수 교체` 패널을 보이고, 현재 사용자가 후보인 행에서 내려갈 출전 선수를 고르게 한다.
16. 플레이 메뉴 첫 화면은 일정 메뉴와 같은 카드 목록 문법을 쓴다. 카드 CTA는 공통 방 모달을 열고, 플레이 메뉴 안에 별도 점수판/상세 작업판을 만들지 않는다.
17. 플레이 메뉴에서 열린 공통 방 모달은 기록판과 선수 교체 패널을 슬롯보다 위에 둔다. 일정/매칭 메뉴의 방 모달 순서는 유지한다.
18. 플레이 메뉴 기록판과 기록 입력 패널도 방 모달 공통 panel border/radius/background 토큰을 써서 매칭 방 모달과 같은 테두리 체계를 유지한다.
19. 방모달 큰 제목은 다크/라이트 모두 공통 주황 토큰 `--rb-orange`를 쓴다.
20. 플레이 메뉴 경기 목록 카드도 매칭 메뉴 공개방 카드와 같은 `om-match-card arena-lobby-card` skin을 쓰고, 카드 전체 클릭으로 공통 방 모달을 연다.
21. 방모달 shell은 border/radius/background를 유지하고, 세로 스크롤은 내부 `.arena-lobby-modal-scroll`에서만 처리해 좌우 테두리가 잘리지 않게 한다.
22. 플레이 메뉴 카드 목록은 매칭 메뉴 카드처럼 compact row 높이를 유지한다. 긴 제목, 메타, 요약은 줄바꿈으로 카드 높이를 키우지 말고 한 줄 안에서 잘라낸다.
23. 경기 메뉴 hero 상황판은 매칭 메뉴 hero 상황표와 같은 panel/card/button 토큰을 쓴다. 메뉴별 카운트 수가 달라도 배경, 테두리, 버튼 높이, stat cell 밀도는 같은 리듬을 유지한다.
24. 모바일 기록 입력의 숫자 조절은 직접 키보드 입력만 의존하지 않는다. 점수와 개인 스탯은 `위 화살표 / 숫자 / 아래 화살표` 스테퍼를 쓰고, 직접 숫자 입력은 보조로 유지한다.
25. 모바일 방모달은 backdrop padding을 포함해 viewport 밖으로 나가지 않게 `100dvw` 기준 폭 제한을 둔다. 320px/360px 폭에서도 shell과 내부 패널 오른쪽 테두리가 잘리면 안 된다.

2-2. 개인 기록 점수 입력은 0 기본값을 강제하지 않고, 0 값에 포커스하면 바로 비워져 새 점수를 입력할 수 있어야 한다.

6. 개인 기록 방모달과 기록 목록/최근 기록 행에는 `개인 기록` 표시를 넣어 일반 경기와 구분한다.

## 2026-06-29 검색 결과 카드 동작

## 최상위 원칙

1. 같은 기능은 같은 모양이어야 한다.
   - 공개방/비공개방 카드가 내용은 달라도 구조는 같아야 한다.
   - 매칭 메뉴와 경기 메뉴에서 같은 방은 같은 모달로 보여야 한다.

2. 화면마다 다른 히어로 구조를 만들지 않는다.
   - 홈, 경기, 매칭, 진행, 팀, 나, 설정은 같은 header/hero 기준을 쓴다.
   - 위치, 여백, 글자 크기, 배경 크롭 기준을 통일한다.

3. 라이트/다크는 색과 이미지 시간대만 다르다.
   - 같은 메뉴는 같은 그림 구도와 같은 위치를 쓴다.
   - 라이트는 낮 이미지, 다크는 밤 이미지.
   - 배경 두 장 겹쳐 쓰지 않는다.

4. 카드 안 카드 금지.
   - 카드 안쪽에는 작은 패널을 둘 수 있지만, 떠 있는 카드처럼 보이게 중첩하지 않는다.
   - 구분은 배경 단계, border, padding으로 한다.

5. 정보는 카드에서 줄이고 모달에서 푼다.
   - 목록 카드에 참여자 전체를 넣지 않는다.
   - 목록은 상태/일시/구장/방식/방보기 중심.

6. 모바일 우선으로 깨짐을 막는다.
   - 가로 스크롤 금지.
   - 큰 요약 패널은 모바일에서 제거.
   - 필터는 가로 스크롤이 아니라 줄바꿈.

## 뱃지 원칙

태그 순서:

1. 단계
2. 방식
3. 공개 여부
4. 참가 방식

목록 카드 배지 색은 `MatchListCard`에서 아래 3색으로 정규화한다. 호출 화면이 다른 tone을 넘겨도 목록 카드에는 별도 색을 추가하지 않는다.

| 의미 | 색 |
| --- | --- |
| 단계·정보 (`waiting`, `locked`, `live`, `record`, 경기 방식) | blue |
| 처리 필요 (`checkin`, `postgame`, `dispute`, 희망 상대) | orange |
| 종료·보조 정보 (`cancelled`, `void`, 공개 여부, 참가 방식, 경기 종류, 심판) | neutral |

`green`, `gold`, `violet`, `danger` tone은 공통 목록 카드 안에서 각각 `blue` 또는 `orange`로 변환한다. 일정·매칭·플레이 목록은 모두 이 규칙을 공유한다.

금지:

- 공개확정
- 일반
- 사전등록 남발
- FLOW 접두어
- 카드 제목에 상태 중복 표기

3. 2명 이상일 때만 파티 표시.
4. 혼자 남은 파티는 표시하지 않는다.
5. `o-o-o` 느낌의 연결선을 넣는다.
6. 연결선은 텍스트와 아바타를 가리지 않는다.
7. 모바일에서는 연결선보다 전체 배경/테두리 우선.

## 프로필/호버 원칙

데스크톱:

- hover로 카드 표시.
- 클릭하면 카드 고정.
- 카드 고정 중 다른 hover 카드 금지.

모바일:

- 탭/길게 누르기로 카드 표시.
- 프로필 페이지 이동은 카드 안 `프로필 보기`.
- 선수/팀/구장/심판 모두 같은 규칙.

팝업:

- 최상단 포털.
- 부모 카드에 잘리면 안 됨.
- 아래 공간 없으면 대상 상단 기준 위로 표시.
- 외부 클릭 시 닫힘.

## 라이트 모드 원칙

1. 다크용 검은 투명 박스를 그대로 쓰지 않는다.
2. 카드와 내부 패널 색 차이가 보여야 한다.
3. 작은 글씨 대비를 확보한다.
4. 아바타 배경 경계가 보이면 마스크/배경을 조정한다.
5. 배경 사진은 낮 이미지.
6. 테두리만으로 구분하지 않고 배경 단계도 둔다.
7. 하단 메뉴는 회색 덩어리로 보이지 않게 밝은 민트/블루 계열 flat surface를 쓰고 gradient를 넣지 않는다.

## 모바일 원칙

1. 가로 스크롤 금지.
2. 하단 메뉴 한 줄.
3. 하단 메뉴가 본문을 가리면 본문 padding-bottom 조정.
4. 필터 버튼은 줄바꿈.
5. 큰 요약 패널 제거.
6. 카드 내부 긴 정보는 접거나 숨긴다.
7. 기록판은 한 화면에 최대한 5명 보이게.
8. 개인활약은 3칸 x 2줄.
9. 모달 액션 버튼은 손가락으로 누르기 충분한 높이.
10. 주소창/하단 메뉴 때문에 가려지는 영역 고려.
11. 기록방 요약은 점수/개인활약/파울을 말줄임하지 않고 줄바꿈으로 전부 읽히게 한다.
12. 모바일 슬롯 액션/초대 팝업은 슬롯 좌표에 매달지 않고 화면 안쪽 중앙 sheet로 띄운다. 초대 검색 결과는 팝업 안 inline 목록으로 크게 보여서 선택 버튼이 숨거나 화면 밖으로 잘리지 않게 한다.
13. 달력 날짜 칸은 경기 수 배지가 있어도 행 높이가 바뀌지 않게 고정한다.
14. `dispute` 방 모달은 경기 관계자가 점수판을 열람하고 새로고침할 수 있다. 점수판 수정/저장은 심판 또는 방장에게만 보이며 저장 결과 메시지는 기록판 안에 짧게 표시한다.
15. `record` 방 모달은 읽기 전용이다. 채팅 입력, 슬롯 관리, 초대, 방 수정 버튼을 보이지 않는다.

## 홈 디자인 원칙

홈은 대시보드가 아니라 액션 허브다.

구성:

1. 검색/빠른 진입.
2. 처리 필요.
3. 내 일정 요약.
4. 최근 기록.
5. 나 메뉴 기록 화면은 최근 6개월 상세 기록과 날짜별 count를 먼저 보여준다. 오래된 기록은 전체 상세 카드가 아니라 텍스트/집계형 목록으로 분리한다.
6. 팀/랭킹 요약.

원칙:

- 검색 기록 영역 제거.
- 처리 완료된 액션은 즉시 사라짐.
- 단순 대기중 방은 홈 액션에 넣지 않음.
- 모집방 목록과 결과 승인 대기 목록은 홈에서 표시하지 않음.
- 카드 그라데이션 혼자 튀지 않게 통일.
- 랭킹/모드별 티어는 2x2 기준으로 정렬.
- 홈 `매칭 만들기`/`경기 기록하기` CTA는 검색 패널 오른쪽에 같은 크기로 둔다. 랭킹/경기/팀/매칭 중복 빠른 링크는 검색 패널 옆에 두지 않는다.
- 홈 Action Queue의 방 초대 row는 `수락`/`거절`/`보기`를 같은 row 안에 둔다. 모바일에서는 버튼을 줄바꿈해 row 밖으로 넘기지 않는다.
- 검색 입력은 공용 `SearchPicker`를 쓴다. 입력 즉시 아래에 결과를 띄우고, 화면 목적에 맞는 대상만 검색한다.
- 방만들기 심판 초대는 native select가 아니라 공용 `SearchPicker`를 쓰고, 심판 자격이 있는 후보만 검색한다.
- 방만들기 구장 선택은 등록 구장 선택이 필수다. 선택이 없으면 CTA 근처에 차단 사유를 보여주고 생성하지 않는다.
- 설정의 요청 폼은 신뢰도/권한 조건을 제출 버튼 근처에 먼저 보여주고, 조건 미달이면 버튼을 비활성화한다.

## 경기/매칭 디자인 원칙

경기:

- 내 일정 중심.
- 캘린더와 목록 정렬 일치.
- 과거 필터는 달력 표시 범위.
- 확정 이후 방은 경기 메뉴에서 같은 모달로 열림.

매칭:

- 대기방 중심.
- 방 카드에서 참여자 제거.
- 필터는 접기 가능.
- 첫 목록은 내 지역 중심이다. `전체 지역` 토글을 기본 필터로 두지 않고, 나중에 시군구 선택 필터로 확장한다.
- DB 기본 제목 `모집방`은 사용자가 쓴 방제처럼 카드 제목으로 강조하지 않는다.
- 모바일 큰 표시판 제거.
- 방보기 버튼은 명확하게.

## 진행 디자인 원칙

1. 진행 중/기록 필요 경기와 확정 후 24시간 이내 평가 가능한 경기만 보여준다.
2. 예정 경기에는 기록판을 보여주지 않는다.
3. 기록 확정 후 24시간이 지난 경기는 경기 메뉴에서 숨기고 나/팀 기록 화면에서만 보여준다.
4. 모바일 기록판은 촘촘하되 터치 가능해야 한다.
5. 점수는 자동 합산이 보이게 한다.

## 팀 디자인 원칙

1. 팀 카드는 엠블럼 중심.
2. 프로필 사진 장식 제거.
3. 골드3 같은 텍스트 티어는 줄이고 엠블럼으로 표시.
4. 즐겨찾기 버튼은 카드 핵심 흐름을 방해하면 제거.
5. 멤버 행은 이름/포지션/역할만 정렬.
6. 오버플로우 금지.
7. 팀 허브 히어로 스타일은 유지 가능.
8. 새 팀명은 경기/매칭 방 요약 박스 기준으로 14자를 넘기지 않는다.
9. 팀 만들기 홈 코트는 native select가 아니라 방 만들기와 같은 구장 전용 `SearchPicker` 검색 기준을 쓴다. 검색창은 선택값과 분리해 비워 두고, 즐겨찾기 또는 추천 구장을 focus popup 안에 보여주며 결과에는 주소를 표시한다. 홈 코트 선택은 한 팀당 하나다.
10. 팀 엠블럼 이미지는 원형 공용 `TeamEmblem` 안에서 `object-fit: contain`으로 전체를 보여주고, 카드마다 별도 색상 점을 만들지 않는다.
11. 팀장용 엠블럼 업로드·변경·삭제는 팀 상세의 기존 관리 카드 안에 두며 별도 중첩 카드를 만들지 않는다.
12. 업로드 control은 데스크톱에서 미리보기·설명·액션 한 줄, `720px` 이하에서 액션 한 줄을 아래로 내려 가로 overflow를 만들지 않는다.
13. 업로드 이미지는 투명 여백을 유지한 정사각 WebP로 정규화하고 이니셜 fallback의 크기·테두리·간격을 그대로 사용한다.

## 설정 디자인 원칙

1. 데스크톱에서 좌우 컬럼 높이 균형.
2. 긴 학습자료는 별도 페이지.
3. 신고/심판/구장 등록은 카드 분리.
4. 구장 등록의 주소검색/좌표변환은 같은 폼 안에서 보조 액션으로 배치.
5. 관리자 메뉴 진입은 권한자에게만 보이는 별도 카드로 둔다.
6. 설정 페이지가 세로로 지나치게 길어지면 분리.
7. 즐겨찾기 관리는 나 메뉴가 아니라 설정 메뉴의 전용 카드에서 한다. 프로필/팀/구장/심판은 각 10개 한도를 표시하고, 관련 검색창의 focus popup과 검색 결과 별 토글에 연결한다.

## 관리자 디자인 원칙

1. 관리자 메뉴는 전체 신고를 시간순으로만 쌓지 않는다.
2. 기본 축은 구장별, 플레이어별, 경기별 정렬이다.
3. 왼쪽은 정렬 큐, 오른쪽은 선택 항목 상세로 둔다.
4. 관리자 화면도 일반 콘텐츠 카드 규칙을 따른다.
5. 임명 관리는 `권한 관리` 업무 탭으로 분리하고, 구장/플레이어/경기 검토 큐보다 먼저 쌓아 보이지 않는다.
6. 처리 액션은 선택 상세 안에 배치하고 신고자 피드백을 기본으로 보여준다. 제재 기간과 대상 선택은 제재 액션을 골랐을 때만 보여준다.
7. 플레이어 큐는 신고/요청/제재가 있는 대상만 보여주고 전체 플레이어를 나열하지 않는다.
8. 플레이어, 구장, 경기 심사는 같은 좌우 workbench를 쓰되, 선택 상세 상단에 현재 심사 축과 처리 기준을 짧게 표시한다.
9. 신고가 여러 개면 최종판단 전에 처리할 신고를 select로 고르게 한다.
10. 관리자 임명 카드는 임명, 연장, 회수 액션을 같은 `admin-action-panel` 안에서 처리한다.
11. 처리 액션은 서버 로그가 붙기 전까지 mock 안내를 같이 노출한다.
12. 관리자 기본 진입은 `구장 신청`이며 상단 업무 탭에서 구장 신청, 플레이어 신고, 경기 심사, 권한 관리를 전환한다.
13. 구장 신청 상세는 신청자, 주소, 좌표, 구장 속성, 승인 액션을 먼저 보여준다. 실제 신고가 없으면 공용 신고 처리 폼을 노출하지 않는다.
14. 관리자 큐는 `처리 대기`를 기본으로 열고 승인·기각된 항목은 `전체 이력`에서 확인한다.
15. 구장 승인 상세는 신청 시설명, 자동 표준명, 검색 기준 주소, 핀 기준 실제 주소, 도로명·지번, 좌표, 지도 링크를 한 흐름에서 확인한다.
16. 같은 장소의 등록·신청 코트를 비교 목록으로 보여주고, 주소·지도 확인 및 복수 코트 확인이 끝나야 승인 버튼을 활성화한다.
17. 최고관리자에게만 `MMR·신뢰도` 업무 탭을 추가한다. 사용자별 점수 수정이 아니라 이벤트 반영률과 증감값을 그룹별 숫자 입력으로 조절한다.
18. 정책 입력은 한 카드 안에서 `개인 MMR`, `경기 형식`, `팀 MMR`, `경기 신뢰도`, `방 운영 신뢰도` 섹션으로 구분한다. 섹션을 다시 카드로 감싸지 않는다.
19. 정책 저장 영역은 현재 버전, 변경 사유, 기본값 초안 적용, 저장 상태를 함께 보여준다. 모바일은 필드와 저장 액션을 한 열로 내려 가로 스크롤을 만들지 않는다.
20. 정책 저장은 공통 확인 팝업에서 적용 시점과 비소급 원칙을 다시 확인한 뒤 실행한다.

## CSS 원칙

1. 새 색상 직접 추가 전 `tokens.css` 확인.
2. 반복되는 카드/패널 스타일은 공통 클래스로 묶는다.
3. 컴포넌트 크기를 내용에 맡기지 않는다.
4. 슬롯/보드/버튼은 고정 또는 clamp 기준 치수 사용.
5. `vw` 기반 font-size 금지.
6. letter-spacing 음수 금지.
7. 보라/남색/베이지/갈색 단일톤으로 밀지 않는다.
8. 라이트/다크 override는 같은 selector 구조로 둔다.

- 텍스트가 버튼/카드 밖으로 나가지 않는가.
- 카드 안 카드가 생기지 않는가.
- 배경 이미지가 중복되지 않는가.
- slot width가 출전/후보에서 같은가.

수정 후:

- desktop dark.
- desktop light.
- mobile dark.
- mobile light.
- 방 모달.
- 카드 목록.
- hover/popup.
- 하단 메뉴.

## 메뉴 간 디자인 통일 원칙

같은 정보군은 메뉴가 달라도 같은 구조와 같은 표면을 쓴다.

- 기록: 홈 최근 전적, 나 메뉴 최근 기록, 나 메뉴 전체 기록은 같은 `recent-match-row` 행 구조를 쓴다.
- 수치: 팀 카드 기록, 나 메뉴 통계, 홈 요약 수치는 같은 metric tile 구조를 쓴다.
- 필터: 경기 메뉴 필터와 매칭 메뉴 필터는 줄바꿈 가능한 버튼/셀렉트 구조를 쓴다. 가로 스크롤 금지.
- 필터 active 상태는 라이트/다크 모두 배경과 글자색을 같이 지정해 대비를 유지한다.
- 방 목록: 경기 메뉴와 매칭 메뉴 방카드는 같은 요약 박스 구조를 쓴다. 외형 차이는 허용하지만 정보 계층은 같아야 한다.
- 라이트 모드: 회색 면을 기본값으로 쓰지 않는다. 흰색/민트 계열 표면과 명확한 내부 패널 차이를 둔다.

2. 소속 입력은 공용 floating `SearchPicker` 하나가 검색과 새 이름 입력을 겸한다. 기존 결과는 소속명과 인원수를 한 행에 표시하고 선택 후 명시적인 `소속 저장`을 눌러 확정한다.
3. 운영 안내는 placeholder 안에 넣지 않고 검색창 바로 아래 helper 문단으로 둔다. 무인증, 30일 변경 간격, 신고 가능 범위, 운영자 수정·통합 가능성을 저장 전에 읽을 수 있어야 한다.
4. 변경 제한 중에는 다음 변경 가능일을 form helper로 표시하고 저장·해제 버튼을 비활성화한다. 별도 경고 modal을 만들지 않는다.
5. 소속명·팀명 신고는 기존 카드 안의 compact 보조 버튼으로 열고, 사유 select와 `신고 접수`·`닫기` 두 액션을 공용 `NameReportForm`으로 사용한다. `520px` 이하에서도 두 액션은 같은 폭의 2열을 유지한다.
6. 관리자 `팀·소속` 업무는 엠블럼·팀명·소속명 신고를 한 queue에서 구분한다. 이름 수정 입력과 소속 통합 대상 검색은 해당 액션을 선택했을 때만 표시하며, 기존 플레이어·경기·구장 queue 배치를 바꾸지 않는다.

## 2026-07-21 구장 신청 정보 입력

1. 구장 신청의 유형·분류·바닥·형태·비용은 추정 기본값 대신 `확인 필요`를 먼저 표시한다. 확인하지 않은 항목을 긍정 또는 부정 체크 상태로 보이지 않는다.
2. 유형/분류, 바닥/형태, 이용 방식/비용은 데스크톱 2열과 모바일 1열의 기존 `form-grid two`를 사용한다. 별도 카드나 모달을 추가하지 않는다.
3. 야간 조명은 야외를 선택했을 때만 표시한다. 공식 안내·예약 링크는 선택 입력이며 잘못된 URL 안내는 기존 form helper 영역에 표시한다.
4. 관리자 구장 신청 상세는 구장 속성과 이용 정보를 분리하고, 유효한 공식 링크가 있을 때만 기존 외부 링크 control로 노출한다.
5. 새 입력은 공용 input/select 토큰을 그대로 사용해 dark/light 색상과 `320px` 모바일 가로폭을 유지한다.
6. 지도 핀 선택 dialog의 상단 닫기는 공용 원형 icon button, 하단 취소·주소 확정은 각각 secondary·primary button 위계를 사용한다. 모바일에서는 상태 문구 아래 두 액션을 같은 행에 배치한다.
7. 구장 신청 목록의 빈 상태는 앱 공용 UI 폰트·크기·굵기로 통일하고 전체 등록 구장 수를 함께 표시하지 않는다.

## 2026-07-21 유료 구장 모집방 표시

1. 매칭·일정의 공용 목록 카드는 유료 구장일 때 기존 주황 계열 `유료 구장` badge를 추가한다. 별도 빨강 계열을 만들지 않아 목록 badge는 주황·파랑·중립 세 색 안에서 유지한다.
2. 공용 방 모달은 참가·팀 합류·선수 초대 수락 전에 `유료 구장입니다.` 확인 dialog를 한 번 표시한다. 취소와 계속 참여는 공용 secondary·primary 버튼 위계를 사용한다.
3. 무료 또는 비용 확인 전 구장은 경고를 띄우지 않는다. 심판 참여는 구장비 참가 확인 대상에서 제외한다.

## 2026-07-21 경기 무효·복구 심사 UI

1. 이의 처리 액션은 `수정안 확정`, `이의신청 반려`, `경기 무효 처리`를 서로 다른 문구로 표시한다. `무효 처리`처럼 대상이 불명확한 단독 문구는 쓰지 않는다.
2. 경기 무효는 공용 `app-confirm` dialog를 사용한다. 10자 이상 사유, 기록·MMR 중단과 방장 신뢰도 차감 안내, 강한 조치 확인 checkbox가 모두 충족돼야 danger 버튼을 활성화한다.
3. 무효 경기 상세에는 저장된 사유를 읽기 전용으로 먼저 보여준다. 복구 권한이 있는 참가자에게만 10자 이상 복구 사유 입력과 `무효 경기 복구 요청` 보조 버튼을 표시한다.
4. 관리자 무효 경기 심사는 처리 선택과 별도 제재 선택을 분리한다. 제재 대상·기간은 제재를 선택했을 때만 표시하고, 50%/100% 반영 방식은 액션 아래 helper로 설명한다.
5. dialog와 관리자 폼은 기존 surface, line, radius, primary/secondary/danger 토큰만 사용하며 새 경고색을 추가하지 않는다. `320px`에서도 textarea와 두 액션이 viewport를 넘지 않아야 한다.
